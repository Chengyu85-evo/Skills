## R1 现状 / 预期对照

功能点**默认渲染成对照结构**，不要写成单向陈述。

❌ 单向：
> 支持双击 pin 内容，最多 pin 3 个。

✅ 对照：
| 功能点 | 现状 | 预期 |
|---|---|---|
| pin 交互 | 仅支持右键菜单「固定」 | 新增双击 pin；最多同时 pin 3 个 |

优化类需求尤其不能省——读者需要知道差异在哪，而不是重读一遍现在的逻辑。

「预期」栏要写到可判定：写"优化布局体验"不合格，写"pin 区域按共享 > AI 视图 > 参会人排列"才合格。

## R2 条件三件套

涉及提示、引导、onboarding、toast、tooltip 等有生命周期的元素时，**三项必须成套生成**，缺一项就向用户追问：

1. **展现条件**，并标明判定关系：`（满足所有条件）` 或 `（满足任一）`
2. **退场条件**，同样标明判定关系
3. **频控**：单次会话 / 单设备 / 单用户最多几次，换设备或重新进入是否重置

示例：

```
展现条件（满足所有）：
- 本场会议未开启过 AI 总结
- AI 视图有节点内容生成
- 单次进入有内容的 AI 视图达到 20s
- 当前未展现付费提示

退场条件（满足任一）：
- 点击【开启 AI 总结】
- 在 toolbar 直接开启开关
- 点击 X

频控：当次入会每设备最多展示一次；离会再入会可能再展示；同 uid 换设备可能再展示。
```

## R3 文案分视角

同一操作对不同角色展示不同文案时，**必须分视角写全**，不要只写一份。

```
关闭 AI 视图后的 toast：
- 主持人视角："已关闭 AI 视图"
- 参会人视角："主持人已关闭 AI 视图"
```

权限受限态也要写：不可操作时的 tooltip、置灰后的点击反馈。

例：非主持人可见入口但不可点，hover 提示"请联系主持人关闭 AI 视图"。

## R4 规则穷举 + 兜底

排序、替换、收起、优先级、裁切这类规则型需求，**穷举优先级后必须补兜底句**。

```
收进 more 的优先级：头像 > 视频流 > 本人 > AI 缩略图 > 共享缩略图 > AS
兜底：极端情况下，可能都被收起。
```

除优先级本身，还要覆盖：

- **数量达上限**时的行为（拒绝？替换？替换哪一个？）
- **状态恢复**：临时顶替结束后是否恢复原状
- **跨状态继承**：切换布局/场景/页面后行为是否保留
- **中断重入**：离开再回来是否记忆
- 必要时补设计原则，例："每次变化顶替最近一个可顶替的 block，尽量减少布局跳变"

## R5 FG 双向表现

每个 FG 写全三项，缺一不可：

```
byteview.vc.ai_layout
- 命中：本人组织的会议有 AI 视图，参会人命中 fg 可见
- 未命中：本人组织的会议无 AI 视图，参会人无论是否命中 fg 都不可见
```

多 FG 有组合关系时补组合表现表。已全量的 FG 标注状态（如"已全量，排除字节"）。

**FG 说明一律写在正文或表格，不写进标题。**

## R6 决策轨迹保留

- 被推翻的方案**用删除线保留在原地**，不要删除
- Change Log 写清**为什么改**，不只写改了什么
- 方向反转时明确写出反转，例："Pin 区域顺序**不再**取决于 pin 顺序，改为始终遵循：共享、AI 视图、参会人"
- 已废弃的埋点项同样用删除线保留

价值在于半年后回看能知道当初为什么这么定，避免重复讨论同一问题。

## R7 不确定性显式标记

未定的地方用 `TBD` / `WIP` / `（待确认）` 显式标记，不要用模糊表述掩盖。

多方案未收敛时保留开放结构：

```
后续付费计划（TBD）
- Plan A：AI 视图消耗 AI 额度，单场只开视图消耗 20 点，双开 40×系数？
- Plan B：作为 pro 功能
- Plan C：……
```

风险要明写并给定性结论：`风险点：默认展示会导致资源消耗激增 —— 接受`。

所有 TBD / WIP 在附录「待确认项汇总」里聚合一份。

## R8 单一职责

一个 PRD 只讲一件事。涉及多场景（如录音 + 会议）时拆分文档，并在开头 callout 声明边界。

判断依据：如果「方案设计」里出现两组互不影响的功能点，考虑拆分。

## R9 引用与锚点

- 引用其他文档用飞书文档引用（`cite`），不要裸贴 URL
- 指向本文档某处时用锚点链接（`文档URL#block_id`），不要写"见上文""见下方"
- 文案表、埋点表用 bitable / sheet 引用，保持可跳转
- 数据结论附查询链接，便于复核

## 交付前检查清单

逐条核对，不通过则修正后再交付。

**硬门禁（不通过不允许交付）**

- [ ] 第 3 节非空，且落在三种填法之一（数据驱动 / 采纳+护栏 / 显式声明不设观察）
- [ ] 占位符 `X` `Y` `N` 已替换成实际数值，或明确标注待定
- [ ] 每个 FG 都有命中 + 未命中双向表现
- [ ] 有生命周期的提示元素，展现条件 / 退场条件 / 频控三项齐全
- [ ] 改动了正文的话，Change Log 已同步加行

**内容完备性**

- [ ] 功能点用「现状 / 预期」对照，不是单向陈述
- [ ] 「预期」写到可判定，不是"优化体验"这类模糊表述
- [ ] 竞品分析后有「我们的取舍」
- [ ] 优先级规则有兜底句
- [ ] 数量上限、状态恢复、跨状态继承、中断重入均已覆盖
- [ ] 文案按视角拆分，含权限受限态
- [ ] 文案 / 埋点有"本次新增"清单，不只给表格链接
- [ ] 影响端表格的责任人列已填（未定填"待定"）
- [ ] 涉及用户内容处理时，合规与安全评估非空
- [ ] Change Log 超过 3 条或跨多篇 PRD 时，有「当前生效规则」快照

**格式规范**

- [ ] 开头 callout 四个入口齐全（Meego / Figma / 文案 / 埋点），暂无的写"待补"
- [ ] Change Log 在顶部，不在附录
- [ ] 标题层级连续，无 `#` 直接跳 `###`
- [ ] 编号无重复、无跳号
- [ ] 标题里没有塞正文（FG 说明、长逻辑说明应在正文）
- [ ] 截图 / 录屏有 caption
- [ ] TBD / WIP 已在附录汇总
