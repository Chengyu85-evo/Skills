# 中文产品经理简历生成

## 核心流程

1. 经历信息不完整时，先通过采访补齐原始材料
2. 从全部经历中提炼一条清晰的核心故事线，不平均罗列所有工作
3. 对排版有要求时，先生成可直接编辑的 HTML 简历
4. 根据用户批注同步修改内容与版式
5. 每次内容变化后重新渲染并检查整张 A4 页面，包括视觉重心、信息密度、模块间距、换行和截断
6. 仅在用户确认 HTML 后导出 PDF
7. 验证最终 PDF 为一页 A4、上下平衡且没有内容截断

## 采访重点

优先追问能够成为简历证据的信息：

- 任职时间、产品或团队、目标用户和职责范围
- 需要解决的问题或发现的机会
- 候选人亲自主导的部分
- 方案为什么不显然、没有成熟参考或存在交付难点
- 产品形态、交互决策和策略判断
- 业务或用户指标的前后变化
- 跨团队复杂度、评测体系和稳定交付过程
- 外部反馈、竞品跟进和内部影响力

区分以下几类贡献，避免混在一句话里：

- 产品形态定义
- 效果与稳定交付
- 增长或业务结果
- 用户洞察与体验判断

## 故事线选择

围绕目标岗位建立统一定位，不把每段经历写成同等重要。

面向 AI、工具效率和 Agent 类岗位时，优先突出：

- 在缺少成熟范式的方向定义新产品形态
- 将 AI 输出转化为可理解、可消费、可稳定交付的产品体验
- 复杂工具、生产力产品和协同效率经验
- C 端内容消费、用户旅程与国际化经验
- 有具体项目支撑的用户体验与产品审美判断

降低以下内容的优先级：

- 指标过多、缺少主线的零散增长优化
- 只体现执行过程、不体现产品判断的工作
- 会冲淡目标岗位定位的次要项目

新增经历时保持层级：先写最强成果，再写小而美的探索或相邻职责，不让补充经历稀释主故事线。

## 内容规则

- 用户未要求时，不写求职意向
- 用户要求或学校背景较强时，将教育经历放在前面
- 个人优势优先使用 3 条简洁 bullet，每条表达一个独立竞争力
- 不写“作为补充”等暴露写作目的的表达，直接概括该段经历的重点
- 不解释招聘者能够自行推断的背景
- 每条经历以行动开头，并由产品判断或结果支撑
- 优先采用“问题 → 产品形态或方法 → 结果”的表达结构
- 避免堆砌指标，只保留最具代表性的结果
- 全文统一产品名称和术语
- HTML 主体保持可直接编辑
- 用户没有特殊偏好时，bullet 与摘要末尾不加句号
- 删除 bullet 时，只把最有区分度的证据融入摘要，不把全部执行细节搬进摘要
- 能力标签必须由整体经历支撑。优先使用“用户体验驱动的产品判断”等准确表述，避免证据不足时使用“交互驱动”或“审美驱动”
- 用已经体现出来的产品方法替代抽象能力词，例如用“从复杂业务场景中抽象原子能力”替代“复杂信息架构”
- 润色时保留“主导”“独立设计”、用户分层、评测维度和跨团队手段等所有权与产品方法信号，不因压缩文字而削弱个人贡献
- 用户明确修改的事实与措辞优先级最高，不擅自改变业务含义

## 推荐结构

一页中文产品经理简历依次包含：

1. 页眉：姓名、精简个人标签、手机号、邮箱
2. 教育经历
3. 个人优势
4. 按时间倒序排列的工作经历

每段工作经历包含：

- 左侧产品或团队与角色，右侧任职时间
- 一段便于快速浏览的灰色摘要
- 3 至 4 条按重要性排列的核心经历；确有必要时允许增加次要探索

## 写作方式

使用直接、高密度的中文简历表达。

推荐句式：

`从 0 到 1 设计/主导/负责 X，围绕 Y 提出 Z，推动 A 指标从 m 提升至 n`

摘要遵循以下规则：

- 说明职责范围和核心产品判断
- 尽量控制在一行；承载关键评测或交付证据时最多两行
- 合并被删除的 bullet 时，最多保留 2 至 3 个高信号信息，例如评测体系、稳定交付和外部验证
- 使用灰色或较轻字重，与正文形成层级

个人优势遵循以下规则：

- 尽量控制为 3 条
- 每条表达不同的竞争力
- 所有能力都能在工作经历中找到具体证据

## 一页 A4 排版规则

- 将页面设置为 A4 比例，并检查浏览器截图或 PDF 渲染结果
- 把每次内容修改都视为排版修改，即使只是删除文字也要重新渲染整页
- 测量首个可见内容块上边缘和最后一个内容块下边缘相对 A4 页面的距离，不能只检查页数或是否溢出
- 上下留白明显不一致时，整体移动内容块或重新分配模块间距；不要仅为填满页面而缩小或放大字号
- 同步维护屏幕 `.page` 的 padding 与打印 `@page` 的 margin，确保 HTML 确认后的构图能够延续到 PDF
- 模块间距需要有清晰区分，同时保持紧凑
- 不使用嵌套卡片或无意义装饰块
- 竖线影响对齐时直接移除
- 以黑色和灰色为主，只增加克制的辅助色
- 用户未指定时不使用深蓝色
- 姓名需要突出，但不能过大
- 日期和联系信息右对齐
- 通过调整文字、宽度、字号或间距，避免一两个字单独换行
- 统一加粗逻辑，通常只加粗项目或能力名称与关键指标
- 检查最后一行是否完整显示

## 改稿后验收门槛

不能只检查“一页、未溢出”就结束改稿。

1. 对比内容变化，确认哪些文字被新增、删除或扩写，以及哪些模块的层级和密度受到影响
2. 每次实质性修改后生成完整 A4 截图，包括仅删除内容的情况
3. 测量页面顶部到首个内容块的 `top_gap`，以及最后一个内容块到页面底部的 `bottom_gap`
4. 仅需垂直居中时，计算 `shift = (bottom_gap - top_gap) / 2`，按该距离移动内容，并同步调整屏幕 padding 与打印 margin
5. 检查模块节奏、标题与日期对齐、摘要长度、bullet 密度、加粗逻辑和一两个字的异常换行
6. 最后一次文字或间距调整后再次渲染；即使只增加一个字，也可能改变换行
7. 仅当页面为一张 A4、视觉平衡、没有截断且不存在明显换行缺陷时，才算完成

## HTML 与 PDF 执行要求

- 使用一个静态 HTML 文件
- 在主页面容器上设置 `contenteditable="true"`
- 使用包含 `@page { size: A4; }` 的打印样式
- 导出 PDF 前先生成浏览器截图供用户确认
- 每次重要内容修改后，检查截图并测量上下留白、页面高度、内容底部和 `scrollHeight`
- 每次改写后重新检查一两个字的异常换行；页面能放下不代表排版合格
- 用户确认后再通过浏览器渲染导出 PDF
- 使用 PDF 工具验证页数与页面尺寸

用户仍在提供内容或排版批注时，不主动导出 PDF；除非用户明确要求
