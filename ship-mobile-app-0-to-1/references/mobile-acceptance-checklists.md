# 移动端验收清单

只使用与当前产品形态和能力相关的部分。不要为了勾选清单扩大产品范围。

## 目录

1. 通用移动端
2. 数据真实性与持久化
3. 相机与相册
4. 图像分割与贴纸效果
5. PWA
6. 原生 App
7. 发布

## 1. 通用移动端

### 屏幕与布局

- [ ] 在最小和最大目标宽度下无横向溢出。
- [ ] 内容不会被刘海、灵动岛、状态栏或 Home Indicator 遮挡。
- [ ] 底部导航和主按钮保留安全区。
- [ ] 地址栏伸缩、横竖屏或键盘出现时没有严重跳动。
- [ ] 固定定位元素不会遮住核心内容。
- [ ] 超长文案、系统大字体和真实图片不会撑破容器。

### 交互

- [ ] 主要触控区域足够大且不重叠。
- [ ] 点击、双击、长按和滑动不存在意外冲突。
- [ ] 横向标签可滚动，页面纵向滚动仍正常。
- [ ] 返回、取消和关闭不会丢失未提示的数据。
- [ ] 加载中禁止重复提交。
- [ ] 成功、失败和权限拒绝都有明确反馈。

### 状态

- [ ] 首次打开为空状态，没有假记录或假统计。
- [ ] 有数据、无数据、加载、失败和离线状态均可访问。
- [ ] 刷新和重新打开后状态正确。
- [ ] 日期、时区和跨月边界正确。

## 2. 数据真实性与持久化

- [ ] 所有统计只从真实记录计算。
- [ ] 测试 fixture 不会进入生产初始化。
- [ ] 新增、编辑、删除后所有页面同步更新。
- [ ] 删除有明确结果，必要时有确认或撤销。
- [ ] 数据迁移不会复制、损坏或复活旧记录。
- [ ] 本地存储失败有降级或错误提示。
- [ ] 清理站点数据、卸载或换设备的丢失风险已告知用户。
- [ ] 若承诺同步，已真实验证多设备冲突与离线恢复。

## 3. 相机与相册

### 权限与生命周期

- [ ] 首次允许、拒绝、系统永久拒绝均有正确路径。
- [ ] 切到后台再回来后相机可恢复。
- [ ] 切换前后摄像头时禁用快门，直到取得真实视频帧。
- [ ] 离开拍照页后释放摄像头。
- [ ] 不支持相机时提供合理的相册或文件降级。

### 构图一致性

- [ ] 快门结果与预览中看到的 cover 裁切一致。
- [ ] 前置摄像头的镜像预览和保存结果符合产品预期。
- [ ] 拍摄 canvas、展示图片和后处理使用同一方向与裁切坐标。
- [ ] EXIF 旋转得到正确处理。
- [ ] 不出现黑帧、黑边、白边或未填满窗口。
- [ ] 相册中的超大图、竖图、横图和低清图不会撑破页面。

### 真实设备

- [ ] 至少在首要真机上验证，而非只用模拟器。
- [ ] 相册选择和翻转摄像头图标含义明确。
- [ ] 连续拍摄、取消、重拍和快速切镜头不崩溃。

## 4. 图像分割与贴纸效果

建立固定回归集，至少覆盖：

- 复杂背景和桌面杂物。
- 深色、浅色、透明或反光主体。
- 主体较小、偏心或部分遮挡。
- 边缘轻微模糊。
- 主体与背景颜色接近。
- 相机拍摄和相册导入。

每次算法变更检查：

- [ ] 可接受样本的识别成功率没有明显倒退。
- [ ] 主体关键结构基本完整。
- [ ] 不残留大块背景或独立杂物。
- [ ] 图片与 mask/描边使用同一坐标系。
- [ ] 描边连续、清晰、封闭且颜色为纯色。
- [ ] 模糊边缘由封闭轮廓补足，不使用模糊阴影冒充描边。
- [ ] 原始大图和透明图不会突破展示容器。
- [ ] 失败原因区分权限、模型、资源、输入和后处理，不统一伪装成“未识别”。

## 5. PWA

- [ ] 通过 HTTP/HTTPS 打开，不依赖 `file://`。
- [ ] manifest 名称、图标、主题色和启动地址正确。
- [ ] iPhone 添加到主屏幕后图标和名称正确。
- [ ] standalone 模式顶部和底部安全区正确。
- [ ] 首次在线加载、再次打开和离线降级符合预期。
- [ ] Service Worker 缓存版本与核心资源版本同步更新。
- [ ] 部署后不会因旧缓存持续展示前一版本。
- [ ] 构建产物路径和静态资源路径符合托管平台要求。
- [ ] 生产控制台没有阻断性错误或资源 404。
- [ ] 明确说明 PWA 与原生 App 的能力差异。

## 6. 原生 App

- [ ] Bundle ID/package name、签名和版本号正确。
- [ ] 相机、相册、通知、定位等权限文案准确。
- [ ] 冷启动、热启动、后台恢复和内存警告可处理。
- [ ] 不同系统版本和目标机型通过测试。
- [ ] TestFlight/APK 安装路径已由真实设备验证。
- [ ] 隐私清单、数据用途、账号删除和商店材料符合实际能力。
- [ ] 崩溃和关键错误有可定位信息。

## 7. 发布

- [ ] 工作区无意外未提交改动。
- [ ] 功能分支基于最新主分支。
- [ ] 构建、测试和适用的视觉/媒体回归全部通过。
- [ ] 用户体验的是待发布的同一 commit。
- [ ] 用户确认后才合并和部署，除非其明确要求直接发布。
- [ ] 主分支、远端主分支和部署 commit 一致。
- [ ] 部署后打开生产地址检查核心路径、控制台和资源。
- [ ] 只向用户提供一个最新体验入口。
- [ ] 交付信息包含已完成、未完成、数据风险和已知限制。
